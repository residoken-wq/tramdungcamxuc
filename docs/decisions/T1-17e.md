## 4. Phân tích nguyên nhân gốc rễ và giải pháp: Lag reload trang đơn hàng

### Hiện tượng

Trong kịch bản kiểm thử E2E thanh toán (task T1-12c), ghi nhận tỷ lệ ~1/14 lần reload trang `/thanh-toan/don/[token]` sau khi admin bấm "Xác nhận đã thanh toán" gặp độ trễ khoảng 2 giây mới hiển thị trạng thái `paid`.

### Phân tích nguyên nhân kỹ thuật (Root Cause Hypothesis)

1. **Thiếu chỉ thị `revalidate = 0` của Next.js App Router**:
   - Trước đây trang `page.tsx` chỉ khai báo `export const dynamic = 'force-dynamic'`.
   - Trong kiến trúc Next.js App Router, `force-dynamic` bảo đảm trang được render theo request, nhưng nếu không có `revalidate = 0`, các cơ chế fetch cache nội bộ hoặc sub-request caching có thể tái sử dụng dữ liệu tạm trong thời gian rất ngắn.
2. **Cơ chế Browser Cache / Conditional Request (304 Not Modified)**:
   - Các phản hồi trước đây không có header `Cache-Control` cụ thể nên trình duyệt (Chromium trong Playwright hoặc trình duyệt người dùng) có thể tự động áp dụng heuristic caching.
   - Khi script kiểm thử gọi `page.reload()` liên tiếp ngay sau API call xác nhận thanh toán, trình duyệt có thể đọc response từ bộ nhớ tạm (Memory Cache / Disk Cache) của lần tải trước đó (vẫn mang trạng thái `pending`). Sau khoảng 2 giây, cache trình duyệt hết hạn thì lần reload tiếp theo mới hiển thị `paid`.
3. **Độ trễ commit / read-after-write của cơ sở dữ liệu**:
   - Khi admin confirm đơn, thao tác ghi vào Postgres diễn ra trong transaction. Dù API trả về HTTP 200, nếu kết nối DB qua connection pooler hoặc môi trường ảo hóa chịu tải I/O cao, một request reload diễn ra chỉ sau vài mili-giây có thể rơi vào khe hẹp đọc dữ liệu trước khi index được flush hoàn tất.

### Giải pháp kỹ thuật đã áp dụng

1. Thêm `export const revalidate = 0` vào `src/app/(site)/(shell)/thanh-toan/don/[token]/page.tsx` để vô hiệu hóa hoàn toàn mọi lớp cache dữ liệu ở tầng Next.js.
2. Bổ sung header cấm cache tuyệt đối tại `src/proxy.ts` cho mọi URL bắt đầu bằng `/thanh-toan/don/`:
   ```http
   Cache-Control: no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0
   Pragma: no-cache
   Expires: 0
   ```
   Header này buộc mọi trình duyệt và proxy trung gian (Vercel Edge Network, Cloudflare, Nginx) luôn gửi request mới về server, không bao giờ dùng bản lưu và không bao giờ trả về HTTP 304.

### Cách kiểm chứng

1. Kiểm tra Network tab trong DevTools: Mọi yêu cầu tới trang `/thanh-toan/don/[token]` phải trả về mã `200 OK` (không có `304 Not Modified` và không có `(disk cache)`).
2. Kiểm tra Response Headers xác nhận có đủ `Cache-Control: no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0`.
