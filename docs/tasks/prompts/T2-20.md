## 1. Làm (mỗi mục 1 commit)

1. **Migration + field** (`pnpm payload migrate:create`, tên `customer_session_version`):
   - `customers.sessionVersion` (number, mặc định 0, bắt buộc): `admin.hidden: true`; `access.read` / `access.update` chỉ admin (khách không đọc / sửa qua REST).
   - `trialUsage.product`: bỏ `required` (cột cho phép null) – khóa ngoại Payload sinh sẵn là `ON DELETE SET NULL`, nên xóa hẳn một sản phẩm có dấu vết dùng thử không còn lỗi. **Không** sửa tay khóa ngoại sang `CASCADE` (lệch với schema Payload). Kiểm chỗ đọc `trialUsage` chịu được `product = null` (khóa `usageKey` cũ giữ nguyên). `down` trả về như cũ (`SET NOT NULL` sau khi xóa dòng null), có `IF EXISTS`.
2. **Thu hồi phiên** (`// REVIEW-REQUIRED:` mọi chỗ):
   - Token khách thêm `sv` (= `sessionVersion` lúc đăng nhập). `verifyCustomerToken` giữ nguyên chữ ký hàm; token cũ không có `sv` coi như `0` (khách đang đăng nhập **không** bị văng ra khi deploy).
   - `customerAuthStrategy` và `getCurrentCustomer`: `sv` khác `customer.sessionVersion` → coi như chưa đăng nhập.
   - `logoutAction`: tăng `sessionVersion` bằng **một câu UPDATE** (`session_version = session_version + 1`) rồi xóa cookie. Hệ quả: đăng xuất là đăng xuất **mọi thiết bị** – ghi rõ trong `decisions` và câu chữ nút (nếu đổi chữ → `vi.ts`).
   - Admin đổi email khách (hook `beforeChange` của `customers`, chỉ khi `email` thực sự đổi) → tăng `sessionVersion`.
   - Xóa tài khoản (T2-16) giữ nguyên.
3. **Phiên khách không đè phiên admin**: trình duyệt có cả cookie khách `tdcx_customer_token` và phiên admin hợp lệ → `/admin` và REST trả về **admin**. Sửa **trong** `customerAuthStrategy` (vd. gọi `JWTAuthentication` của Payload trước; có user admin hợp lệ → strategy khách trả `{ user: null }`). Đọc mã nguồn Payload để chắc không đệ quy / không chạy JWT hai lần tốn kém; ghi lý do vào `decisions`. Trang khách (`getCurrentCustomer` đọc cookie riêng) vẫn thấy khách.
4. **Test**:
   - unit `tests/unit/customer-session.test.ts`: đăng xuất → token cũ bị từ chối (strategy lẫn `getCurrentCustomer`); token không có `sv` vẫn hợp lệ khi `sessionVersion = 0`; admin đổi email → token cũ bị từ chối; khách gửi `PATCH /api/customers/:id` với `sessionVersion` → không đổi; strategy khách trả `null` khi request có JWT admin hợp lệ; xóa sản phẩm có `trialUsage` → xóa được. Dữ liệu `[TEST]`, `@example.test`, xóa khách bằng `context: { accountDeletion: true }`, **chỉ** dọn dữ liệu mình tạo.
   - e2e `tests/e2e/admin-with-customer-cookie.test.ts`: khách đăng nhập OTP (mẫu `tests/e2e/tracker.test.ts`: IP riêng `x-forwarded-for`, tick đồng ý, chờ Turnstile, `toPass`; bộ chọn lỗi **bỏ qua** `#__next-route-announcer__` như `tests/e2e/eq-saved.test.ts`) → cùng trình duyệt đăng nhập admin → `/admin` mở được danh sách; → đăng xuất khách → `/tai-khoan` đòi đăng nhập lại.
