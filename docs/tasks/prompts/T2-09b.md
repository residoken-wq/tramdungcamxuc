## 1. Làm

Đọc **toàn bộ** biên bản QA:

```bash
git --no-pager show origin/main:docs/tasks/reviews/T2-09.md
```

Sửa **hết mục A, B, C**. Mỗi nhóm một commit (`fix(payment): …`, `test(payment): …`, `docs(payment): …`). Cách sửa:

1. **A1 – nhánh 401 không giữ chỗ `transactionId`.** `// REVIEW-REQUIRED:`.
   - Event `invalid_signature` **không** đặt `transactionId` (để rỗng). Muốn giữ mã thì để trong `rawPayload` (đã có sẵn trong body).
   - Giới hạn kích thước body: đọc `req.text()`, quá 16 KB → 413, ghi event không kèm body; rồi mới `JSON.parse`.
   - Test: gửi khóa sai với `id = X` → sau đó gửi webhook hợp lệ `id = X` → đơn `paid`, có quyền.
2. **A2 – bật được SePay trên production.** Được phép sửa `docker-compose.prod.yml` (chỉ thêm 2 dòng):
   ```yaml
   PAYMENT_PROVIDER: ${PAYMENT_PROVIDER:-manual}
   SEPAY_WEBHOOK_API_KEY: ${SEPAY_WEBHOOK_API_KEY:-}
   ```
   RUNBOOK mục SePay: mọi chỗ `restart app` → `docker compose -p tdcx-demo -f docker-compose.prod.yml up -d < /dev/null` (cả bước bật lẫn bước quay về `manual`), ghi rõ "`restart` không nhận biến mới".
3. **B1 – rate limit.** Thứ tự mới trong route: (404 nếu không phải sepay) → đọc body → **kiểm khóa** → chỉ request **sai khóa** mới qua rate limit (theo IP) → ghi event → 401. Request đúng khóa không bị rate limit. IP lấy **phần tử cuối** của `X-Forwarded-For` (do reverse proxy của mình thêm), không có thì `x-real-ip`, không có nữa thì `'unknown'` (vẫn đếm). Viết thành hàm nhỏ trong `src/lib/payments/` (không sửa các file `actions.ts` khác). Ghi lý do vào `decisions`.
4. **B2 – event và trạng thái đơn khớp nhau.** `// REVIEW-REQUIRED:`.
   - Ghi event với `result: 'processing'` (`result` là trường text, không cần migration).
   - Gọi `markOrderPaid`:
     - thành công → cập nhật event `result: 'paid'`;
     - `InvalidOrderStatusError` → đọc lại đơn, cập nhật event theo trạng thái thật (`order_cancelled` / `already_paid` / `ignored`), trả **200**;
     - lỗi khác → **xóa** event vừa ghi (để SePay gửi lại xử lý được), log, trả 500.
   - 2 giao dịch khác nhau cùng 1 đơn song song → event thua race là `already_paid`.
   - Test: hủy đơn giữa lúc webhook (giả `markOrderPaid` ném `InvalidOrderStatusError`) → event `order_cancelled`, 200; giả lỗi DB → 500 và không còn event → gửi lại → `paid`.
5. **B3 – `terms_missing`** cảnh báo nổi bật trong admin như `amount_mismatch`; thêm vào `HUONG_DAN_CMS.md` (Hana làm gì: liên hệ khách tick điều khoản, hoặc xác nhận thủ công).
6. **B4 – unit test** (`tests/unit/sepay.test.ts`):
   - Bộ gửi email giả (theo mẫu `tests/unit/digital-tool-order.test.ts`): đúng tiền → 1 email; gửi trùng / song song → vẫn 1 email.
   - Song song và 2 giao dịch: đếm `entitlements` của khách = đúng số mong đợi.
   - Route: thiếu header → 401; thiếu `SEPAY_WEBHOOK_API_KEY` → 401.
   - Dọn sạch: mọi entitlement, audit log, paymentEvents, rate_limit_hits, đơn, khách do test tạo (lọc theo id / email test); xóa theo thứ tự con trước cha; không `catch {}` rỗng – dùng `.catch((e) => console.error(...))`.
   - Email `@example.test`. Env dùng `vi.stubEnv` + `vi.unstubAllEnvs()` trong `afterEach`.
7. **B5 – RUNBOOK**: nghiệm thu bằng sản phẩm thử giá 2.000đ (`saleStatus = hidden`, xóa sau) hoặc chuyển đúng tổng đơn.
8. **C1 – `OrderPaymentEvents.tsx`**: chỉ dùng CSS variables / màu trong 8 màu brand (đọc skill `tdcx-brand`; admin Payload cho phép biến `--theme-*` sẵn có); chữ và nhãn kết quả tiếng Việt vào `vi.ts` (khối `payment`); tài liệu khớp màu thật.
9. **C2 – `OrderPaymentView.tsx`**: 1 khối thành công + 1 nút; chữ nút theo loại đơn (công cụ số → vào công cụ; khác → "Xem tài khoản"); poll cả đơn `failed`; hết 15 phút hiện câu "Tải lại trang để kiểm tra"; bỏ emoji; `motion-reduce` nếu có hiệu ứng.
10. **C3–C6**: `Cache-Control: no-store` cho route trạng thái; bỏ import vòng (`getPaymentProvider` import `SepayPaymentProvider` ở đầu file, `sepay.ts` không import ngược `provider.ts` – tách type chung nếu cần); giá trị `PAYMENT_PROVIDER` lạ → `console.warn` một lần và dùng `manual`; JSON lỗi → ghi event `invalid_payload` rồi 400.
11. **C7–C9 – tài liệu, Prettier**: sửa `decisions/T2-09.md` theo biên bản (file đúng, hành vi đúng, bỏ "Vietcombank", ghi `rawPayload` có thể chứa tên người chuyển, lý do không có e2e, giới hạn `accountNumber`); `HUONG_DAN_CMS.md` bỏ "hoàn trả / chuyển trả tiền thừa" → "liên hệ khách để xử lý"; Prettier trên mọi file đã sửa.
