# EB-10 – Header / footer dựng bằng builder (giao: Claude Code, **Laptop**)

Spec: `docs/plan/BUILDER_ELEMENTOR.md` (mục 3 dòng "Theme Builder", mục 4 task EB-10: "Header / footer dựng bằng builder (thay Navbar / Footer code khi site chọn), giữ footer pháp lý bắt buộc").
Quyết định trước: `docs/decisions/EB-04.md` (`_style`), `docs/decisions/EB-07.md` (khoá khối, menu chuột phải), `docs/decisions/EB-08.md` (mẫu, lịch sử phiên bản), `docs/decisions/EB-09.md` (CSS / HTML tuỳ chỉnh, `guardCustomCodeHook`, mục 6 EB-09c).
Review gần nhất: `docs/tasks/reviews/EB-08.md`, `docs/tasks/reviews/EB-09.md`.
AGENTS: §5B ("khoá … footer pháp lý"), §8.1 (menu chính, 6 trang pháp lý ở footer mọi trang), §11 (a11y).
Ước lượng: 8 h. **Có migration (🔒 Migration – tạo migration cuối cùng, ngay trước khi nộp).**

**Bối cảnh:**

- Mọi trang công khai dùng chung layout `src/app/(site)/(shell)/layout.tsx`: `Navbar` (client, có menu con desktop / mobile từ SM-02.4, nút CTA, tài khoản khách) + `<main>` + `Footer` (6 trang pháp lý, thông tin người bán, mạng xã hội, tagline) + `FloatingActions`.
- Dữ liệu lấy từ `getSiteShellData()` (`src/lib/site-shell.server.ts`) – global `navigation` + `siteSettings` + `legalPages`.
- Trang dựng bằng Puck nằm ở collection `pages`, render qua `StyledRender` (`src/components/design/StyledRender.tsx`). Wrapper gốc có `data-eb-page` (EB-09), CSS trang tuỳ chỉnh bị giới hạn trong wrapper đó.

**Mục tiêu:** Hana dựng **đầu trang** và **chân trang** bằng chính builder (khối, Container, `_style`, mẫu, lịch sử phiên bản), rồi chọn dùng bản builder thay cho Navbar / Footer code. Mặc định site **vẫn dùng bản code**, không ai thấy khác cho tới khi chủ site chuyển.

**Không làm (BACKLOG):** điều kiện hiển thị theo trang (header khác cho `/habit`…), header trong suốt đè lên hero, mega menu, popup, theme builder cho trang chi tiết.

## Quyết định Planning (không hỏi lại)

1. **Lưu ở đâu:** thêm field `kind` vào collection `pages`.
   - Kiểu `select`: `page` (mặc định) | `header` | `footer`. Chỉ chọn được lúc tạo, sau đó `readOnly`.
   - Trang `header` / `footer` dùng lại toàn bộ builder, bản nháp / xuất bản, lịch sử phiên bản EB-08, autosave.
   - Slug tự sinh, không cần nhập (ví dụ `__dau-trang-<id>`), và field slug ẩn với 2 loại này.
   - Trang `header` / `footer` **không bao giờ** được:
     - truy cập công khai: `[...slug]` và trang chủ chỉ tìm `kind = page`;
     - nằm trong sitemap;
     - chọn được làm trang đích ở menu (`navigation`), thư viện, `detail-pages`;
     - được nhân bản thành trang thường.
   - Rà mọi chỗ `collection: 'pages'` (`grep -rn "collection: 'pages'" src`) và thêm điều kiện `kind`.
2. **Chọn dùng bản nào:** global `navigation` thêm nhóm "Đầu trang / chân trang":
   - `headerSource` (`code` | `builder`, mặc định `code`) + `headerPage` (relation `pages`, `filterOptions` `kind = header`);
   - `footerSource` / `footerPage` tương tự.
   - **Chỉ `owner` sửa được nhóm này** (field-level `access.update`). Editor vẫn sửa menu như cũ.
   - `builder` mà trang chọn chưa có bản xuất bản, hoặc lỗi khi đọc → layout **tự quay về bản code**, không bao giờ để trang công khai mất header / footer.
   - Lỗi khi đọc thì ghi log server.
3. **Render:** layout đọc `navigation` (đã cache bằng `react` `cache` trong `getSiteShellData`).
   - Khi dùng builder, render bản đã xuất bản qua `StyledRender` với **config riêng cho header / footer**:
     - root render ra `<header data-eb-header>` / `<footer data-eb-footer>`, không phải `<div data-eb-page className="min-h-screen …">`;
     - CSS tuỳ chỉnh của root header / footer giới hạn trong `[data-eb-header]` / `[data-eb-footer]`: thêm tham số phạm vi cho `sanitizePageCustomCss`, **không** sửa luật lọc của EB-09c, có unit test.
   - `EntranceAnimator` chỉ gắn **một lần** mỗi trang: thêm prop tắt cho `StyledRender`.
   - Khách đang đăng nhập (tên, email) truyền qua `metadata` của `<Render>` (Puck 0.23 – đọc docs `Render` / `metadata`). Không đọc cookie trong khối.
4. **Khối mới** (`src/puck/blocks/site/`, nhóm sidebar "Đầu / chân trang", **chỉ có** khi sửa trang `header` / `footer`):
   - `SiteLogo` – logo từ `siteSettings` + link về trang chủ; chọn cỡ S / M / L, không nhỏ hơn 120 px ngang (Brand Book).
   - `NavMenu` – menu chính từ `navigation` (có menu con).
     - Desktop: hàng ngang. Mobile: nút mở menu + bảng trượt, giống hệt Navbar hiện tại.
     - **Tách** phần menu trong `Navbar.tsx` thành component dùng chung (ví dụ `NavMenuView`) để Navbar code và khối dùng **cùng một** mã. Navbar code phải render **y hệt trước** (e2e / unit SM-02 giữ xanh).
     - Prop: căn trái / giữa / phải, điểm chuyển sang mobile (`md` | `lg`).
   - `HeaderCTA` – nút CTA của `navigation` (nhãn / link từ CMS, không nhập lại).
   - `AccountLink` – "Đăng nhập" / tên khách (đọc từ `metadata`).
   - `LegalFooter` – 6 link pháp lý từ `legalPages` theo `order` + thông tin người bán (`sellerInfo`). **Bắt buộc** trong trang `footer`:
     - không xoá / không nhân bản được: permissions, dùng lại `getLockedComponentPermissions` – đã có sẵn nhánh `LegalFooter`;
     - kiểm ở server khi lưu / xuất bản (giống `validatePageLockedBlocks` cho Hero trang chủ), ở **hook collection**, không chỉ trong action (bài học EB-08 C3, EB-09 C4);
     - trang công khai: footer builder thiếu khối này (dữ liệu cũ, lỗi) → layout tự gắn dải pháp lý code ở cuối.
   - `SocialLinks` – link mạng xã hội từ `siteSettings`. `Tagline` – câu tagline.
   - Mọi khối lấy dữ liệu bằng `resolveServerData` (`src/puck/resolve.server.ts`), **chỉ lưu tuỳ chọn hiển thị**, không lưu bản sao link / chữ (AGENTS §5B).
   - Khối chung dùng được trong header / footer: `Container`, `HeadingWidget`, `TextWidget`, `ImageWidget`, `ButtonWidget`, `IconWidget`, `IconListWidget`, `Spacer`, `Divider`, `HtmlWidget` (theo luật owner EB-09).
   - Các khối khác (form, lưới sản phẩm, Hero…) **không** có trong header / footer.
   - Ngược lại, khối "Đầu / chân trang" **không** có trong trang thường.
   - Lọc theo `kind` trong `getPuckConfig({ kind })` (sidebar), và kiểm ở server khi lưu (khối không thuộc loại trang → từ chối).
5. **Root props:**
   - header: `sticky` (`none` | `sticky`, mặc định `none`); khi `sticky` thì `position: sticky; top: 0` + `z-index` cố định dưới modal / toast của site;
   - cả hai: `customCss` (chỉ owner + `lock.customCss` mở, như EB-09).
   - Nền, khoảng cách: Hana dùng `Container` + `_style`, không thêm field màu tự do.
6. **Mẫu sẵn:** 2 mẫu "Đầu trang mặc định" / "Chân trang mặc định" trong `src/puck/templates/`.
   - Dựng bằng khối mới + Container sao cho trông **gần giống nhất** Navbar / Footer code hiện tại.
   - Tạo trang `header` / `footer` mới → tự nạp mẫu tương ứng (như `applyTemplateOnCreate`).
   - Mẫu theo đúng định dạng / validate của EB-08.
7. **Lối vào cho Hana:**
   - Trong admin, danh sách `pages` có cột / lọc `kind`.
   - Nhóm mới trong `navigation` có nút "Chỉnh sửa trực quan" mở `/builder/<id>` của trang đã chọn.
   - Editor hiện tên loại ("Đầu trang" / "Chân trang") ở thanh trên.
   - Canvas header / footer hiện **khung trang giả** phía dưới / trên (vài dòng xám, `aria-hidden`) để Hana thấy vị trí, không lưu vào dữ liệu.
8. **A11y:**
   - Giữ landmark `<header>`, `<nav aria-label>`, `<footer>`.
   - Giữ link "Bỏ qua tới nội dung" (`#noi-dung`) nếu Navbar có.
   - Menu mobile đóng bằng Esc, giữ focus như Navbar.
   - Tương phản WCAG AA.
