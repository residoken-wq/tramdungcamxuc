## 1. Làm (mỗi mục 1 commit, push sau mỗi commit)

1. **Field `status`** trong `habitCheckins` (nhãn tiếng Việt vào `vi.ts`, khối `hb04`):

   | Giá trị   | Nhãn           | Nghĩa                                         | `done`  |
   | --------- | -------------- | --------------------------------------------- | ------- |
   | `voted`   | Bỏ phiếu       | Làm đủ hành động đã cam kết                   | `true`  |
   | `minimal` | Bản tối giản   | Làm bản dưới 2 phút (giữ chuỗi, tính vào 90%) | `true`  |
   | `missed`  | Lỡ nhịp        | Học viên tự ghi hôm nay lỡ                    | `false` |
   | `rest`    | Nghỉ theo nhịp | Học viên ghi ngày nghỉ                        | `false` |
   - `required`, **không** đặt `defaultValue` ở schema (bản ghi mới luôn có `status` do hook / server action đặt).
   - **Giữ field `done`** (không xóa cột): hook `beforeChange` mới `syncDoneFromStatus` luôn đặt `done = status ∈ {voted, minimal}`. Có `status` thì `status` thắng; chỉ có `done` (API / code cũ) thì suy ra `status = done ? 'voted' : 'missed'`. Mọi chỗ đang đọc `done` (chứng nhận, thống kê, nhắc lỡ nhịp) chạy y như cũ. Đánh dấu `// REVIEW-REQUIRED:` (ảnh hưởng tỷ lệ 90%).
   - `done` trong admin: `readOnly` + mô tả "Tự tính từ trạng thái". `defaultColumns` thêm `status`.
   - **Chưa** chặn `rest` vào ngày bỏ phiếu hay `voted` vào ngày nghỉ – đó là luật nhịp tuần HB-05. Ghi rõ trong decisions.

2. **Migration** `pnpm migrate:create hb04_checkin_status`:
   - Thêm enum + cột `status` (cho phép `NULL` lúc thêm cột), rồi **backfill** trong cùng `up`: `UPDATE habit_checkins SET status = 'voted' WHERE done = true;` và `UPDATE … SET status = 'missed' WHERE status IS NULL;` rồi mới `SET NOT NULL` (nếu Payload sinh `NOT NULL` ngay thì sửa tay thứ tự cho đúng). Kiểm SQL sinh ra.
   - `down`: gỡ cột + enum (cột `done` còn nguyên nên không mất dữ liệu).
   - `pnpm generate:types`.

3. **Server action** `src/lib/habit/tracker-actions.ts`:
   - Zod: thêm `status` (enum 4 giá trị, tùy chọn). Giữ `done` (tùy chọn) để giao diện hiện tại chạy tiếp. Phải có ít nhất 1 trong 2; có cả 2 thì `status` thắng. Lỗi tiếng Việt.
   - Ghi `status` vào cả 3 chỗ tạo / sửa / tranh chấp unique. Kết quả trả về thêm `status`, giữ `done`.
   - Giao diện hiện tại (chỉ gửi `done`) **không** phải sửa: `true` → `voted`, `false` → `missed`.

4. **Test** (`tests/unit/habit-checkin-status.test.ts`, DB, dữ liệu tự tạo, dọn sạch):
   - Tạo check-in với từng `status` → `done` đúng bảng trên.
   - Chỉ gửi `done: true/false` (API cũ) → `status` = `voted` / `missed`.
   - Gửi `status: 'minimal', done: false` → `status` giữ `minimal`, `done = true`.
   - Server action: gửi `status`; gửi `done`; không gửi gì → lỗi; khách khác → bị chặn (hook có sẵn).
   - **Bản tối giản tính vào 90%**: kế hoạch 10 ngày, 9 ngày `minimal`, 1 ngày `missed`, qua ngày cuối → đủ điều kiện chứng nhận (`countCompletedVotingDays` = 9).
   - **Backfill**: trên DB test, tạo vài check-in, dùng SQL đặt `status = NULL` cho chúng (mô phỏng dữ liệu cũ), chạy lại đúng câu `UPDATE` của migration (tách thành hàm / hằng SQL dùng chung để test gọi được) → `done = true` thành `voted`, còn lại `missed`.
   - Chạy lại `tests/unit/{habit-journey,habit-plan-fields,certificate,tracker}*` xanh.

5. **Tài liệu**:
   - `docs/decisions/HB-04.md`: 4 trạng thái + ánh xạ `done`, lý do giữ `done`, backfill dữ liệu cũ, `rest` / `voted` theo ngày để HB-05, bản tối giản tính vào 90% (DECISIONS 2b – Hana xác nhận khi xem thử).
   - `docs/HUONG_DAN_CMS.md` (mục check-in thói quen): cột "Trạng thái" mới, "Đã hoàn thành" giờ tự tính.
