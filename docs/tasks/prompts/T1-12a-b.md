## 1. Làm (4 việc)

1. **Sản phẩm theo `productId`**: `experienceOrderSchema` thêm `productId` (bắt buộc); `createExperienceOrder` tìm đúng sản phẩm đó và kiểm `type = coaching_trial` + `_status = published` (sai → lỗi tiếng Việt `vi.payment.errors.productNotFound`). Bỏ cách "lấy sản phẩm đầu tiên". Test: có 2 sản phẩm `coaching_trial` giá khác nhau → đơn lấy đúng giá của `productId`; `productId` của sản phẩm loại khác → lỗi.
2. **Test tự dọn, không đụng dữ liệu mẫu**: `tests/unit/payments.test.ts` tạo sản phẩm riêng (không `isSample`), truyền `productId`; `afterAll` xóa đơn → audit → customer → sản phẩm do test tạo. Chạy `pnpm test` **cả bộ 2 lần** đều xanh (trước đây chỉ đỏ khi chạy chung với `seed.test.ts`).
3. **Xác nhận chống race**: `confirmManualPayment` cập nhật **có điều kiện** – `payload.update({ collection: 'orders', where: { and: [{ id: { equals } }, { paymentStatus: { equals: 'pending' } }] }, data: … })`; chỉ khi đổi được đúng 1 bản ghi mới ghi audit "paid" và gửi email; không đổi được → coi như "đã xác nhận trước đó". Áp tương tự cho `cancelOrder` và `expirePendingOrders`. Test: gọi `confirmManualPayment` 2 lần **đồng thời** (`Promise.all`) → đúng 1 email.
4. **Chặn sửa thẳng trạng thái**: hook `beforeChange` của `Orders` – khi `operation = update`, nếu `paymentStatus`/`paidAt`/`deliveryStatus` khác giá trị cũ mà `req.context?.paymentAction !== true` → giữ nguyên giá trị cũ (hoặc ném lỗi tiếng Việt "Hãy dùng nút Xác nhận / Hủy đơn"). 3 hàm ở mục 3 truyền `context: { paymentAction: true }`. Test: owner `PATCH /api/orders/:id { paymentStatus: 'paid' }` qua Local API không có context → trạng thái không đổi; qua `confirmManualPayment` → đổi.

Mọi chỗ sửa giữ/ thêm `// REVIEW-REQUIRED:`. Chạy Prettier trên file mình sửa. Không sửa `docs/tasks/**`.
