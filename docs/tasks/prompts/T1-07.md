## 1. Vấn đề cần giải

`products.files` hiện trỏ tới `media` – collection **công khai** (ai có URL là tải được). Tài liệu giao qua email (và sau này tài liệu trả phí) phải nằm ở nơi **không truy cập trực tiếp được**, chỉ tải qua link ký có hạn.

## 2. Làm

1. **Collection upload riêng tư `privateFiles`** (`src/collections/PrivateFiles.ts`, nhãn "Tài liệu riêng tư", nhóm "Bán hàng"): `upload: true` chỉ nhận PDF/ZIP/EPUB, `staticDir` **ngoài** `public/`, `access.read` = owner/editor, tạo/sửa/xóa = owner/editor. Đăng ký thêm vào `s3Storage({ collections: { media: true, privateFiles: { prefix: 'private' } } })` – giữ mặc định đi qua Payload để vẫn kiểm quyền.
2. **Đổi `products.files[].file`** sang `relationTo: 'privateFiles'` (một migration `pnpm migrate:create private_files`). Trước khi tạo migration kiểm DB: `products.files` có dòng nào không – **có → DỪNG, báo lại** (không tự xóa dữ liệu thật).
3. **Token tải** `src/lib/downloads/token.ts` (hàm thuần, không phụ thuộc Payload): `signDownloadToken({ productId, fileId, expiresAt })` / `verifyDownloadToken(token, now)` – HMAC-SHA256 bằng `PAYLOAD_SECRET`, base64url, so sánh `timingSafeEqual`, hạn **7 ngày**. Không lưu token vào DB.
4. **Route tải** `src/app/(site)/api/download/[token]/route.ts` (hoặc chỗ phù hợp không đụng route Payload): token sai/hết hạn/file không còn thuộc sản phẩm → trang/response lỗi tiếng Việt (410 hết hạn, 404 sai); hợp lệ → lấy `privateFiles` bằng Local API rồi **stream** file với `Content-Disposition: attachment` (local: đọc từ `staticDir`; có R2: đọc object bằng S3 client – thêm `@aws-sdk/client-s3` đúng phiên bản mà `@payloadcms/storage-s3` đang dùng). Không redirect tới URL công khai nào. `// REVIEW-REQUIRED:` ở chỗ kiểm token.
5. **Trang** `src/app/(site)/(shell)/tai-nguyen/[slug]/page.tsx`: chỉ hiện product `published`, `type` ∈ {`ebook`,`toolkit`}, `saleStatus = free`; còn lại 404. Hiện ảnh bìa, `shortDescription`, `includes`. Có `files` → form (họ tên, email, ô đồng ý bảo mật có link `/chinh-sach-bao-mat`, honeypot, Turnstile); không có file → "Tài liệu đang được chuẩn bị" (không form).
6. **Form + server**: thêm `submitResourceRequest` vào `src/lib/forms/submit.server.ts` (dùng lại đúng thứ tự T1-06b: honeypot → Zod → Turnstile → rate limit → lead `need = resource`, tag `resource:<slug>`, `source.form = 'resource'`) rồi gửi email `ResourceDeliveryEmail` (`src/emails/`) chứa 1 link ký cho mỗi file + hạn dùng. Email lỗi → lead vẫn lưu, trang vẫn báo "Kiểm tra email". Server action mỏng trong `actions.ts`.
7. **Turnstile phía trình duyệt**: component client `TurnstileWidget` (chỉ nạp script `challenges.cloudflare.com` khi có `NEXT_PUBLIC_TURNSTILE_SITE_KEY`; không có → không hiện, server dev bỏ qua như T1-06). Dùng lại được cho T1-03.
8. **Docker**: thêm volume cho thư mục file riêng tư trong `docker-compose.prod.yml` (giống volume media) để file không mất khi cập nhật image; ghi vào `docs/RUNBOOK.md` 2–3 dòng.
9. Analytics: client gọi `track('lead_submitted')` khi thành công; `resource_downloaded` phía server để T1-15 (ghi BACKLOG).
10. **Test**:
    - Unit: ký/kiểm token (đúng, sửa 1 ký tự, hết hạn, đúng mốc hết hạn, file khác sản phẩm); `submitResourceRequest` tạo lead đúng tag và gọi email sender giả với link chứa token; route tải trả 410/404/200 (dùng file tạm).
    - Quyền: khách chưa đăng nhập `GET /api/privateFiles` và `/api/privateFiles/file/<tên>` → bị chặn.
    - **Viết** (không chạy) e2e `tests/e2e/free-resource.test.ts`: admin tạm tạo `privateFiles` + product free có file; khách mở `/tai-nguyen/<slug>`, gửi form → thấy thông báo; lấy token bằng hàm ký trong test để tải → 200 + đúng `content-type`; URL file trực tiếp → bị chặn; dọn dữ liệu.
11. Quyết định ghi `docs/decisions/T1-07.md`.
